# The vendored EJS solver bundle

These three files are the JavaScript engine of the n-parameter /
signature solver, executed in-process through `rquickjs` (QuickJS-NG)
by `mochy-innertube/src/stream/ejs.rs` — the port of upstream
`utils/sabr/EjsNTransformSolver.kt`, which ran them in an Android
WebView.

| File | What it is | License (verified 2026-11-21) |
|------|------------|-------------------------------|
| `yt.solver.core.js` | The EJS bundle proper (`jsc`): parses a YouTube player script with meriyah, locates the nsig and signature functions structurally, and emits a "preprocessed player" whose `_result.n` / `_result.sig` are the solver functions | **Unlicense** (public domain) — header in the file: "SPDX-License-Identifier: Unlicense, automatically generated by https://github.com/yt-dlp/ejs" |
| `meriyah.js` | The ES parser (UMD build, meriyah 6.1.4) the EJS bundle depends on | **ISC** — "Copyright (c) 2019 and later, KFlash and others", https://github.com/meriyah/meriyah |
| `astring.js` | The AST-to-JS code generator (minified UMD build, astring 1.9.0) the EJS bundle depends on | **MIT** — "Copyright (c) 2015, David Bonnet <david@bonnet.cc>", https://github.com/davidbonnet/astring |

All three are GPL-3.0-compatible (public domain / ISC / MIT); the

root NOTICE.

## Provenance and the one deliberate difference from upstream

`meriyah.js` and `astring.js` are vendored **byte-identical** to the
upstream Android repository's assets (`app/src/main/assets/solver/`
at pin `bde01cb4`), and both match the dependency versions pinned by
the current yt-dlp/ejs release (meriyah 6.1.4 UMD, astring 1.9.0 min
— verified by checksum).

`yt.solver.core.js` is the **current official build** of the same
bundle (esbuild recipe from yt-dlp/ejs `hatch_build.py`: entry
`src/yt/solver/main.ts`, `--format=iife --global-name=jsc`, meriyah
and astring external), replacing the upstream snapshot. The upstream
snapshot turned out to predate every player generation still
fetchable from YouTube: it fails with "found 0 n function
possibilities" on both the live player (STS 20774) and the oldest
player in yt-dlp/ejs' own recorded corpus (STS 20529). The current
build solves both. The decision is recorded in HANDOFF ## Phase 06;
the `jsc` entry contract is unchanged, so this file can continue to
be swapped for newer yt-dlp/ejs releases without code changes.

The esbuild-IIFE build references its two external dependencies
through a `__require(...)` shim instead of the old build's
parameter-injection shape; the Rust loader defines a locked-down
`require` (globals-only) in the engine before evaluating the bundle
(`stream/ejs.rs`).

Do not edit these files: they are upstream artifacts.

## Test fixture

`tests/fixtures/ejs/` holds the recorded n-challenge fixture the
offline acceptance test replays: a delta-debug-trimmed copy of a real
player script plus the recorded challenge/response vectors. See the
`_provenance` field in `challenges.json`.
